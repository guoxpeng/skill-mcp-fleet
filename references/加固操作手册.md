# 第一部分 · 你要做的

## 1. 立刻：处置飞牛上裸奔的副端 ⚠️

审计实测（不带任何凭据，直接调用成功）：

```
GET  http://192.168.1.10:3100/    → auth: None, root: True
POST exec {"command":"id"}       → [exit 0] uid=0(root) gid=0(root)
```

也就是说：**同网段内任何设备（含 5 台 IP 摄像头、访客手机、IoT）都能以 root 身份在 NAS 上执行任意命令**。
而 NAS 上还跑着 `:8000` ms-relay、`:4000` DeeperSeeker、`:5432` postgres。

**最省事的止血**（不用的时候直接停，隧道一并断开）：

```bash
sudo bash /opt/nas_mcp/mcp-ctl.sh stop
```

**想继续用** → 看第 2 节，换成加固版（带令牌）。

## 2. 给飞牛换上加固版（推荐，一条命令）

在飞牛上执行（脚本用新版 install.sh，会自动生成令牌并写入配置）：

```bash
# 把新版 install.sh 传到飞牛后：
sudo bash install.sh --name nas --port 3100 --prefix "" \
    --generate-token --require-auth
```

或者在主端（Windows）一条命令推过去：

```bash
python fleet.py bootstrap --name nas --host 192.168.1.10 --user admin \
    --key <home>\nas-mcp\nas_ed25519 \
    --generate-token --require-auth
```

装完会打印一行 `令牌: xxxxx`。**把它记下来**，主端要用。

## 3. 主端 mcp.json 同步加 headers

副端一旦开了鉴权，主端不带 headers 就会一直 401。把 `~/.workbuddy/mcp.json` 的 `nas` 条目改成：

```json
"nas": {
  "type": "http",
  "url": "http://192.168.1.10:3100/mcp",
  "headers": { "Authorization": "Bearer <上面那个令牌>" },
  "description": "nas 副端 MCP"
}
```

改完**重启 WorkBuddy**（或重载 MCP 配置）才生效。

## 4. 检查路由器：3100 / 8790 有没有做过端口映射

如果做过映射，前面的"裸奔"就是**公网可见**，而不是仅内网。有就立刻撤掉。
（`3100` = 副端 MCP，`8790` = 地址目录）

## 5. 顺手收紧老配置文件权限

```bash
sudo chmod 600 /opt/nas_mcp/mcp_agent_config.json
chmod 600 ~/.mcp-fleet/nodes.json
```

新版安装器已经会**每次安装都无条件收紧**，但老安装不会自愈。

# 第三部分 · 隧道到底安不安全（结论不变）

| 维度 | 实际情况 |
|---|---|
| 传输加密 | ✅ TLS，无问题，也不暴露 NAS 真实 IP |
| 地址算不算秘密 | ❌ `*.trycloudflare.com` 子域可被枚举，"随机即安全"不成立 |
| 客户端证书 | ❌ 没有，能访问该 URL 就是"客户端" |
| 限制来源 IP | ⚠️ 基本不行，走隧道时来源是 cloudflared 本机地址（`allow_ips` 与隧道互斥） |
| 真正的门禁 | ✅ **只有应用层 `auth_token`** |

**结论：隧道的安全性 100% 取决于 auth_token。**
令牌够强（32 字节随机 ✔）、不外泄（v3.1 已堵住投毒链）、目录没被投毒 → 属"可用"；
三条缺任何一条 = 把 root shell 挂到公网上。

**彻底解法（有余力再做）**：公网入口换 **named tunnel（固定域名）+ Cloudflare Access**，
身份认证在 Cloudflare 边缘做，副端根本收不到未认证流量。

# 第四部分 · 还没做的（需要你决策）

1. **named tunnel + Cloudflare Access** —— 需要你的域名，最彻底的方案。
2. **旧工具弃用**：`add_fleet_node.py` / `call_node.py` / `probe_fleet.py`
   完全不支持 token，对 v3.1 副端一律 401；且 `probe_fleet.py` 会**无条件执行一次 exec**。
   建议标注弃用或补 `--token`（本次未动，避免影响你的既有脚本）。
3. **`FLEET_NO_AUTH=1` 二次确认** —— 当前只有大声警告，没有要求输入 yes。
4. **副端降权运行** —— 目前以 root 常驻，理论上可改为专用用户 + sudoers 白名单（改动大，收益中等）。
5. **云容器隧道**：旧的 `judge-defining-salon-benz.trycloudflare.com` 已死（实测 HTTP 000），
   主端 `mcp.json` 里的 `cloud` / `fnos` 两条是死链，建议清理或重跑脚本拿新地址。
