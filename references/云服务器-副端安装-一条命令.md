## 一、这是干什么的？（1 分钟看懂）

### 先打个比方

| 名词 | 好比是 |
|---|---|
| **主端** | 你手里的**遥控器** —— 就是你现在这台 Windows 电脑 |
| **副端** | 装在云服务器上的**接收器** —— 一个一直在后台跑的小程序 |
| **隧道** | 一条从外面通到服务器里的**秘密地道**（服务器在内网，你直接连不上它） |
| **令牌 / token** | **门钥匙**。知道地址但没钥匙，进不去 |
| **终端** | 那个**黑底白字的框框**，在里面打字让服务器干活 |

装好之后，你在自己电脑上说一句话，云服务器就替你干活（跑命令、看日志、管 Docker），
不用每次去云厂商网页上慢慢点。

### 你总共只需要做两件事

1. **复制一段命令**到云服务器，按回车，等 1~3 分钟
2. **把屏幕最后打印的两行**（一个网址 + 一串钥匙）发给我

就这样。下面一步一步来。

---

## 二、第一步：打开云服务器的「终端」

阿里云 / 腾讯云 / 华为云都差不多：

1. 登录云厂商控制台
2. 找到你这台服务器 → 点「**远程连接**」或「**Workbench**」或「**登录**」
3. 屏幕上会出现一个**黑底白字的框框**，光标一闪一闪

**怎么确认打开了？** 框框里最后一行应该以 `#` 或 `$` 结尾，像这样：

```
root@iZbp1xxxx:~#
```

看到了就对了。

> 如果打不开这个框框，先解决它 —— 找云厂商的文档或客服。
> 这一步过不去，后面都做不了。

---

## 三、第二步：把下面这一整段复制进去，按回车

👇 **从 `bash -c` 开始，到最后一个 `'` 结束，全部选中复制**

```bash
bash -c 'set -e; for U in \
 "https://ghfast.top/https://raw.githubusercontent.com/guoxpeng/skill-mcp-fleet/main/install.sh" \
 "https://ghproxy.net/https://raw.githubusercontent.com/guoxpeng/skill-mcp-fleet/main/install.sh" \
 "https://gh-proxy.com/https://raw.githubusercontent.com/guoxpeng/skill-mcp-fleet/main/install.sh" \
 "https://raw.githubusercontent.com/guoxpeng/skill-mcp-fleet/main/install.sh" ; do \
  echo "[*] 尝试通道: $U"; \
  if curl -fsSL --connect-timeout 15 "$U" -o /tmp/mcp-install.sh && [ "$(wc -c < /tmp/mcp-install.sh)" -gt 70000 ]; then \
    echo "[+] 下载成功 $(wc -c < /tmp/mcp-install.sh) 字节"; break; fi; done; \
 md5sum /tmp/mcp-install.sh; bash -n /tmp/mcp-install.sh && echo "[+] 语法校验通过"; \
 sudo bash /tmp/mcp-install.sh --name cloud --port 3100 --tunnel --auth-token "$(head -c 24 /dev/urandom | base64)"'
```

粘贴到黑框框里，按一次**回车**，然后**等 1~3 分钟**。

**屏幕上会滚很多行字，这是正常的，别关掉。**

### 这段命令其实只做了 3 件事

1. 从 3 个国内加速站里挑一个能用的，把安装脚本下载下来
2. 检查下载的东西有没有被改坏（对一下「指纹」md5）
3. 安装 + 启动，最后打印出你需要的**网址**和**钥匙**

### 三个小提醒

- 要**整段**复制，少一个字符都不行
- 粘贴后有的终端不会自动执行，**再按一次回车**
- 如果提示 `Permission denied`（权限不够），在命令最前面加 `sudo ` 再试

## 四、第三步：把打印出来的这两行发给我

装好后，屏幕最后会打印类似这样的东西：

```
============================================================
 公网隧道地址：https://xxxx-xxxx.trycloudflare.com
 MCP 端点    ：https://xxxx-xxxx.trycloudflare.com/mcp
 鉴权 token  ：AbCdEf123456GhIjKl...
------------------------------------------------------------
 本地 agent  ：正常
 域名解析    ：已解析
 公网访问    ：200 (通)
============================================================
```

**你要找的就是这两行：**

| 找这一行 | 里面是什么 |
|---|---|
| `MCP 端点` | 一个 `https://.../mcp` 的**网址** |
| `鉴权 token` | 一串随机字母数字 —— 这就是**门钥匙** |

**把这两行原样复制，发给我。** 我在你的电脑上做最后一步注册，之后就装好了。

> 🔑 **为什么要发我？** 主端要拿这个网址 + 钥匙才能连上副端。
> ⚠️ 但**别发到群里、别发到公开的地方** —— 钥匙给了别人，别人就能操作你的服务器。

| 你看到的字 | 什么意思 | 怎么办 |
|---|---|---|
| `command not found` 里有 `curl` | 服务器没装下载工具 | 先跑 `apt update && apt install -y curl`（CentOS 用 `yum install -y curl`） |

# 附录（第一次装可以跳过）

## 附录 A：完全离线安装（服务器上不了外网时用）

**什么时候用**：第二节那 4 条通道一条都不通（服务器出网被限制）。

**原理**（一句话）：把安装脚本压缩成一段**纯文字**，你想办法把这段文字传进去，
服务器自己解压还原 —— 全程不用联网。

仓库里给了**三个内容一模一样的文件**，看你能怎么把东西传进去，挑一个：

| 文件 | 适合怎么传 | 大小 |
|---|---|---|
| `install-offline.sh` | **推荐**。scp / U 盘 / 内网共享，一个文件搞定 | 43205 B |
| `install-offline.b64` | 只能贴**纯文字**（网页终端、聊天窗口、邮件正文） | 39165 B |
| `install-offline.part01~10.txt` | 单条消息有长度限制时，分 10 段贴 | 每片 4001 B（第 10 片 2657 B） |

### A-1 自解压脚本（最省事）

把 `install-offline.sh` 传到云服务器（U 盘、scp、内网共享都行），然后：

```bash
sudo bash install-offline.sh --name cloud --port 3100 --tunnel
```

它会自己从文件里切出内嵌的安装脚本、**校验指纹**、然后安装。不需要网络。

### A-2 纯文字版

`install-offline.b64` 里**只有 base64 字符，没有任何说明文字** ——
所以下面这条命令是「整文件直接解码」，不用做任何预处理：

```bash
python3 -c "import base64,zlib;open('/tmp/mcp-install.sh','wb').write(zlib.decompress(base64.b64decode(open('install-offline.b64','rb').read())))"
md5sum /tmp/mcp-install.sh        # 应该输出 ba8d4c106adc6185a22c7586f696b46e
bash -n /tmp/mcp-install.sh && echo "[+] 语法校验通过"
sudo bash /tmp/mcp-install.sh --name cloud --port 3100 --tunnel
```

> 正确结果应打印：`88743 字节 / md5 ba8d4c106adc6185a22c7586f696b46e`

### A-3 分片版

10 片**全是纯文字（base64）**，按顺序拼起来就行：

```bash
cat install-offline.part*.txt > install-offline.b64
# 然后照 A-2 的命令还原安装
```

`cat` 是按文件名排序的，`part01`…`part10` 正好是正确顺序。

> 📌 **为什么这里不再内嵌一大段 base64？**
> 老版本把整段载荷**手工贴在本文档里**，每次改安装脚本都要人工同步，极易漏 ——
> 「文档里贴的是 v2.4、仓库里发的是 v2.3」这种事故就是这么来的。
> 现在载荷由 `make-offline.py` 从 `install.sh` **自动生成**，而且能一键校验：
>
> ```bash
> python3 make-offline.py --check     # 逐字节比对 .b64 / .sh / 分片 与 install.sh
> ```
>
> 校验用的是「你实际会敲的那条命令」（整文件解码、朴素 `cat`），
> 不是脚本自己偷偷剥注释 —— 所以上面三条路径是**真的**能跑通。

## 附录 B：安全 —— 为什么一定要设「钥匙」

副端以 **root** 运行，`exec` 工具等于**把云服务器的最高权限挂到公网上**。
v3.0 加了两道闸，v3.1 又把「默认值」改安全了，**开隧道时必须至少用一道**：

| 配置 | 作用 |
|---|---|
| `auth_token` | 门钥匙。请求要带 `Authorization: Bearer <钥匙>` 或 `X-Fleet-Token`。**留空 = 完全不设防** |
| `allow_ips` | 只允许特定 IP 访问。**填了就生效**，不在名单里直接 403 |

```bash
# 安装时指定钥匙
sudo bash install.sh --name cloud --port 3100 --tunnel --auth-token '一串随机'
```

**兜底**：`mcp-tunnel.sh` 发现没设钥匙，会**自动生成**一个 32 字节随机钥匙、
写进配置、重启副端，然后把钥匙打印出来。真不要这层保护（只在完全可信的内网里用）
才用 `FLEET_NO_AUTH=1`（会大声警告）。

另外还有**防暴力破解**：同一个 IP 连续失败 10 次 / 60 秒后，每次失败额外等 1 秒。
钥匙比对用 `hmac.compare_digest`（固定耗时，防止被人靠"听声辨位"猜出来）。

> ⚠️ `allow_ips` 和公网隧道**基本互斥** —— 走隧道时来源显示的是 cloudflared 的本机地址。
> 要公网访问就用钥匙。

主端 `mcp.json` 里对应写成：

```json
{
  "mcpServers": {
    "cloud": {
      "type": "http",
      "url": "https://xxxx-xxxx.trycloudflare.com/mcp",
      "headers": { "Authorization": "Bearer 你的钥匙" }
    }
  }
}
```

## 附录 C：保活 —— 掉线了自动恢复

云服务器会被 OOM、平台重启、隧道掉线打断。保活守护每 60 秒做三件事：

1. **agent 挂了 → 拉起来**
2. **隧道进程没了 → 重建**（*只在进程真的没了时* —— 能复用绝不重建，避免撞 trycloudflare 限流）
3. **把当前地址写进 `current_url.txt`，并上报「地址目录」**

systemd 机型（oneshot + timer，不占常驻进程）：

```bash
systemctl status cloud-mcp-watchdog.timer
systemctl start  cloud-mcp-watchdog.service     # 立刻跑一轮
cat /opt/cloud_mcp/watchdog.log
```

容器机型（常驻循环，`mcp-ctl.sh start` 会自动拉起）：

```bash
bash /opt/cloud_mcp/mcp-ctl.sh watchdog         # 跑一轮 + 看守护状态
bash /opt/cloud_mcp/mcp-ctl.sh wdlog 50         # 看保活日志
bash /opt/cloud_mcp/mcp-ctl.sh keepalive off    # 关掉（或不装：--no-keepalive）
```

## 附录 D：隧道换域名了怎么办（地址自动跟随）

隧道域名一换，主端写死的地址就失效。三步解决：

```bash
# 1) 在一台 7x24 的机器上跑目录服务（NAS / 小主机都行）
python3 fleet-directory.py --port 8790 --token <一串随机>

# 2) 副端安装时告诉它目录在哪
sudo bash install.sh --name cloud --port 3100 --tunnel \
  --directory http://192.168.1.10:8790 --directory-token <同一串>

# 3) 主端登记目录
python3 fleet.py directory --url http://192.168.1.10:8790 --token <同一串>
```

之后主端发现地址不通，会**自动问一次目录、换成新地址并回写登记表**：

```bash
python3 fleet.py sync                     # 手动刷一遍
python3 fleet.py exec cloud "uptime"      # 地址失效时自动纠正后重试
```

>
> 本次实测：`purge` 之后它立刻返回正确的 88743 B（md5 `ba8d4c10…`）。
>

> 不适合放在自动重试的循环里。要绝对稳定，用 **commit SHA 的不可变直链**：
> `https://raw.githubusercontent.com/guoxpeng/skill-mcp-fleet/<commit-sha>/install.sh`

> 下载 cloudflared 那一步，脚本内部也自带国内镜像

## 更新日志

### v3.1（2026-09-19）— 安全加固（按安全审计报告逐条修）

**默认值改安全**
- **默认只绑 `127.0.0.1`**：原来默认 `0.0.0.0`，手滑启动一次就等于全网卡裸奔。
  `install.sh` 生成的 systemd / supervisor 仍然**显式**传 `--host 0.0.0.0`，正常安装不受影响。
- **默认不发任何 CORS 头**：原来对每个响应都回 `Access-Control-Allow-Origin: *`，
  无鉴权时等于让任意网页 `fetch` 本机执行命令**并读到返回值**。需要跨域时在配置里写
  `cors_allow_origins: ["http://localhost:3000"]`，按 `Origin` 精确回显。
- **状态页不再向未认证者吐指纹**：`GET /` 原来会自报 `tool_names` / `root` / `auth` /
  `allow_ips`，等于告诉扫描器「这里有个不带锁的 root shell」。现在只有「配了 token 且校验通过」
  才返回完整信息，否则只回 `{status, server, version}`。

**新增开关**
- `require_auth` / `--require-auth`：没配 `auth_token` 就**拒绝启动**（exit 2）并打印修正命令。
  公网 / 隧道场景建议打开。
- `--generate-token`：还没有令牌就现场生成 32 字节随机令牌并写进配置。
- `max_body_bytes`（默认 1 MB）：`Content-Length` 超限或为负直接 **413**。
  原来无上限，单连接即可占住一个线程或吃满内存。
- `max_sse_conns`（默认 16）：`/sse` 并发上限，超了回 **429**。原来每个 `/sse` 常驻一个线程且无上限。

**修掉的洞**
- **`hmac.compare_digest` 遇非 ASCII 抛 `TypeError`**：HTTP 头按 latin-1 解码，
  攻击者塞一个非 ASCII 字节就能触发未捕获异常、打 traceback 并断连接。
  现在统一按 bytes 比（`surrogateescape`），返回 401。
- **`allowed_roots` 可用软链逃逸**：`os.path.abspath` 不解析软链，在允许目录里放一个指向
  `/etc/shadow` 的软链就能读出来。改用 `os.path.realpath`，前缀用 `os.sep` 拼
  （Windows 上也不会失效）。文档同时写明：**这条边界不约束 `exec`**。
- **令牌权限不自愈**：新增 `save_config()`，每次写配置都**无条件** `chmod 0600`。
  原来只在「首次安装」和「带参数重装」两个分支设权限，重装不带参数时保持 0644
  —— 同机任何用户都能读走 token。

**修复**
- **`--uninstall` 漏删保活定时器**：卸载只删了 `<name>-mcp.service`，忘了
  `<name>-mcp-watchdog.timer` / `.service`。timer 是 `enabled`+`active` 的，
  安装目录被删后它仍**每 60 秒**触发一次 oneshot，而单元里的 `WorkingDirectory`

- **`--auth-token` 在重装时被静默忽略**：配置文件「已存在不覆盖」的副作用。
  现在这些命令行参数会**合并进**已有配置（不传则保留原值）。

### v2.4（2026-09-19）— 修掉一处「重启自杀」

**症状**：通过**副端自己的 `exec` 工具**执行 `mcp-ctl.sh restart` 后，agent 再也没起来，隧道一直返回 **502**。

**根因**：`restart` 原实现是 `stop; sleep 1; start`。`stop` 会把 agent 进程（也就是这条 exec 命令的**父进程**）一起杀掉
→ 后面那句 `start` **永远执行不到**，于是「停掉了但没起来」。

**修法**：把「延迟 start」用 `setsid nohup` **脱离进程组**挂到后台，再执行 `stop`：
```bash
restart)
  if command -v setsid >/dev/null 2>&1; then
    setsid nohup bash -c "sleep 2; bash '$DIR/mcp-ctl.sh' start" >>"$DIR/ctl.log" 2>&1 </dev/null &
  else
    nohup bash -c "sleep 2; bash '$DIR/mcp-ctl.sh' start" >>"$DIR/ctl.log" 2>&1 </dev/null &
  fi
  stop ;;
```

**规则（记住）**：重启副端**要么从容器终端执行**，要么让命令自带 `setsid` 脱离进程组；
**绝不要**直接 `exec` 一条裸的 `mcp-ctl.sh restart`。
