## 〇、核心叙事

**从"主副端"到"Agent 对等网络"：你的所有设备，AI 之间会互相协作。**

> 每台设备装一个「节点」，节点之间**自研协议互联**（UDP 自动发现 + 离线邮箱 + gossip 同步），无需任何外部服务。设备上的 **AI Agent 之间可直接通信** —— 在线直投、离线存邮箱、上线自动收信。
>
> 和"遥控器-接收器"的单向踩控不同，这是一张 **AI 对等协作网**：A 的 agent 可以操控 B，B 的 agent 也可以操控 A，两个 agent 还能互发消息、按能力委派任务、临时组队完成复杂工作。

```text
              ┌─────────── AI 对等网络（自研协议 · 零外部依赖）───────────┐
              │  UDP 广播发现 │ HTTP 消息端点 │ 离线邮箱 │ gossip 同步       │
              └───┬────────────┬────────────┬────────────┬─────────────┘
               云服务器        NAS          办公PC        手机
              ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
              │ 部署/发布 │  │ 数据/影集 │  │ 测试/分析 │  │ 随身入口 │
              └────────┘  └────────┘  └────────┘  └────────┘
  任一节点上的 AI Agent 都可：操控任意节点 / 向任意 agent 发消息 / 按能力委派任务
```

## 一、场景故事（Day-in-Life 实景）

### 故事 1｜一句话管全家设备（个人）

**主角**：阿凯 —— 程序员，家里 NAS、软路由、两台树莓派；办公室开发机；云上两台服务器。

**痛点**：每台设备一个登录方式，忘了密码、找不到 IP、半夜 NAS 报警手忙脚乱。

**接入 Fleet 之后**：

> "这周我所有设备的磁盘、负载、异常日志，整理成一份日报发我。"
> —— agent 通过 mesh 拓扑一次性巡检全部节点，汇总成报告。

> "看看生产服务器下午 3 点 CPU 飙升的原因。"
> —— agent 直连云节点，查 journalctl、看进程、定位代码，在开发机上跑测试复现。

**评委锚点**：真实数字生活 —— AI 从"聊天对象"变成"设备管家"。

### 故事 2｜两个 AI 分工协作（独立开发 / 极客）

**主角**：小微 —— 独立开发者，代码在办公室，测试环境在云上，NAS 上跑 CI。

**痛点**：改代码 → SSH 上测试机跑 → 回办公室看结果，来回切机器浪费半天。

**接入 Fleet 之后**：

> 办公室电脑的 agent 与云主机的 agent 组队：云 agent 负责跑测试，办公 agent 负责改代码。
> "把刚 commit 的代码在云上跑一遍单测，过了就部署到 NAS 的 CI。"
> —— 两个 agent 通过 `msg_send` / `delegate` 分工协作，一条指令完成"改码-测试-部署"闭环。

**评委锚点**：不止"AI 操控设备"，而是 **Agent 与 Agent 的协作调度** —— 明确的技术差异化。

### 故事 3｜断网也能送达的消息（网络不可靠环境）

**主角**：出差中的阿凯，网络时好时坏。

**痛点**：跨设备传文件、让家里主机执行任务，网络一断就失败重试、丢消息。

**接入 Fleet 之后**：

> 出差笔记本的 agent 给家里 NAS 发指令时 NAS 恰好离线 → 消息存入 **outbox 离线邮箱**。
> NAS 上线后经 gossip 同步自动收到并执行。全程**一条消息都不丢**。

**评委锚点**：store-and-forward 离线邮箱是真实可靠性设计，展示"通信协议级"的技术完成度。

## 二、能力演进路线图（展示技术想象力）

### 已实现（v4.4 本次提交）

```text
每个节点：35 个工具（exec/文件/Docker/systemd/日志/系统 + peer 互控 + 消息总线 + agent 协作 + mesh）
自研协议：UDP 广播自动发现 / HTTP /fleet/* 消息端点 / store-and-forward 离线邮箱 / gossip 同步
安全确权：设备码配对 + 邀请链接（TTL + 单次有效 + 显式信任确认）
运行模式：连接模式（temporary/permanent）+ 控制模式（direct/assisted 辅助审查）
零外部依赖：不依赖 Tailscale 或任何外部服务，纯标准库，Python 3.6+ 兼容
```
